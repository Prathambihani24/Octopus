    Where the first pass missed

    A targeted sample checks named fields against official documentation. These are the fields used for corrections, so the comparison measures the fixes on this sample. It does not estimate accuracy across all 100 apps.

    Where a human must verify the result

    The pipeline finds relevant passages and flags possible conflicts. A reviewer confirms the product and API version, checks whether credentials are actually available on the stated plan, and distinguishes test access from customer rollout. For MCP, verify the vendor actually provides a server for this product. Escalate unclear or contradictory docs instead of guessing.

    For each sample below, read the official source before revealing the published row. Record the source and section, your finding, and one outcome: match, correction, or unresolved.     How the 100-app snapshot was produced

    Discover

    Search every app for API, auth, credential access and MCP. Save the source candidates and extract the first result's signals.

    Check the docs

    Read targeted official sources for policy changes, ambiguous product names and mismatches between API and MCP access. Record decisions that need judgment.

    Compare and aggregate

    Score reviewed fields against the retained baseline, then generate category totals and the filterable matrix from the same rows.
